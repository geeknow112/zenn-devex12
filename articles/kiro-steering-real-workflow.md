## 結論

Kiroの設定ファイル（Steering）を整備したところ、**同じ作業が1/3の時間で終わるようになりました**。

具体的な数字は以下の通りです：

| 作業 | Before | After |
|---|---|---|
| 定型作業 | 45分 | 15分 |
| 毎回の説明 | 5〜10回 | 0回 |
| 「どのリポジトリ？」 | 毎回聞かれる | 聞かれない |

この記事では、実際に使っているSteering設定を公開いたします。

## 前提：Kiroとは

AWS公式のAIコーディングアシスタントです。Claude搭載で、VS Code上で動作します。

https://kiro.dev

特徴は「Steering」という仕組みです。`.kiro/steering/` に置いたMarkdownファイルが、AIへの永続的な指示になります。

## Before：何が問題だったか

Kiroに「作業を進めて」と言うと、こうなります：

```
私：作業を進めてください
Kiro：どの作業でしょうか？
私：記事投稿です
Kiro：どのプラットフォームですか？
私：Zennです
Kiro：何を更新しますか？新規記事？既存記事の修正？
```

**毎回この確認が入ります。**

AIは丁寧に確認してくれますが、作業効率は最悪です。

## After：Steeringで「質問禁止」にした

`.kiro/steering/my-workflow.md` を作成しました：

```markdown
---
inclusion: manual
---

# 定型作業

「作業を進めて」と言われたら、以下の手順で作業を開始する。

## 作業の流れ
1. `memo/` フォルダの最新メモを確認
2. 前回の続きから作業を進める
3. **質問せず、メモに記載されている情報で判断して進める**
```

ポイントは最後の一行です。

**「質問せず、推論して進める」**

これを書くだけで、AIの動きが激変します。

## 実際の会話（After）

```
私：#my-workflow 作業を進めてください
Kiro：（memoフォルダを確認）
Kiro：（前回の進捗を確認）
Kiro：前回の続きから作業を進めます。
```

**質問ゼロになりました。**

## Steeringの書き方：3つのコツ

### 1. 「質問するな」を明記する

AIは親切心で質問してきます。それを止めるには明示的に書く必要があります。

```markdown
## 作業ルール
- 不明点があっても質問せず、推論して進める
- 迷ったらmemoフォルダを確認する
- それでも不明ならより安全な選択肢を取る
```

### 2. ファイルパスは具体的に

❌ 悪い例：
```markdown
設定ファイルを確認してから作業
```

✅ 良い例：
```markdown
`memo/memo.YYYYMMDD.md` で当日の作業を確認
```

AIが「どのファイル？」と聞く理由は、パスが曖昧だからです。

### 3. inclusion: manual で呼び出し式に

```markdown
---
inclusion: manual
---
```

これを書くと、チャットで `#ファイル名` と打たないと読み込まれません。

常に読み込む設定（`inclusion: auto`）もありますが、作業別の指示は `manual` が良いです。コンテキストを無駄に消費しません。

## Steeringの例

### user-preferences.md（auto）

```markdown
---
inclusion: auto
---

# ユーザー設定・作業ルール

## メモファイルへの追記ルール
- メモファイルへの追記は、必ずユーザーに確認してから行う
- 勝手に追記しない

## コミュニケーション
- 敬語を使用すること
- 簡潔に回答すること
```

### my-workflow.md（manual）

```markdown
---
inclusion: manual
---

# 定型作業

## 作業の流れ
1. `memo/` フォルダの最新メモを確認
2. 前回の続きから作業を進める
3. 質問せず、メモに記載されている情報で判断して進める
```

## よくある質問

### Q. Claude CodeのCLAUDE.mdと何が違いますか？

Claude Codeは `CLAUDE.md` 1ファイルに全部書きます。

Kiroは複数ファイルに分けられ、`inclusion` で読み込みタイミングを制御できます。

作業別に分けたいならKiroのSteeringのほうが柔軟です。

### Q. AIが指示を無視することはありますか？

あります。特に長いチャットになると忘れることがあります。

対策：
- 重要な指示は冒頭に書く
- 作業ごとにチャットをリセットする
- `#ファイル名` で明示的に再読み込みさせる

### Q. どこまで書けばいいですか？

「毎回説明していること」をすべて書いてください。

2回以上説明したことは、Steeringに書くべきです。

## まとめ

Kiroを賢く使うコツは以下の3点です：

1. **「質問するな、推論しろ」を明記する**
2. **ファイルパスは具体的に書く**
3. **作業別にSteeringを分けて、manualで呼び出す**

これだけで、作業時間が1/3になります。

設定に30分かけても、1週間で元が取れる計算です。

まだSteering書いていないなら、今日から始めてみてください。
